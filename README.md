# 1C Log Detective

![1C Log Detective — диагностика технологических журналов 1С](banner.png)

**1C Log Detective** — инструмент на Python для анализа технологических журналов 1С:Предприятие, исследования блокировок, исключений и проблем производительности.

Проект помогает разработчикам 1С исследовать большие технологические журналы, находить подозрительные операции и получать структурированную диагностическую информацию.

Основное внимание уделяется потоковой обработке данных, анализу SQL-операций, исследованию блокировок и контролю потребления оперативной памяти.

## Возможности

### Разбор технологического журнала 1С

- Потоковое чтение технологического журнала.
- Разбор событий и извлечение временных отметок, типов событий, длительности и параметров.
- Обработка многострочных событий.
- Поддержка основных типов событий технологического журнала.
- Работа с большими файлами без загрузки всего содержимого в оперативную память.

### Анализ исключений EXCP

- Извлечение исключений из технологического журнала.
- Группировка повторяющихся исключений.
- Подсчёт количества повторений.
- Определение времени первого и последнего появления.
- Выделение исключений, связанных с блокировками.
- Подготовка структурированной информации для дальнейшего расследования.

### Анализ блокировок TLOCK

- Разбор событий блокировок.
- Извлечение информации о потоках, ресурсах и областях блокировок.
- Исследование последовательностей событий блокировки.
- Анализ временной близости блокировок и исключений.
- Выявление повторяющихся и потенциально связанных ситуаций.

### Анализ производительности

- Сбор статистики длительности событий по типам.
- Группировка SQL-запросов по типу и нормализованному тексту.
- Подсчёт количества выполнений и статистика длительности SQL-операций.
- Расчёт среднего и максимального времени выполнения.
- Расчёт 95-го перцентиля (P95).
- Выделение медленных операций с порогом по умолчанию 10 мс.
- Анализ таблиц, участвующих в SQL-запросах.
- Формирование списка наиболее затратных SQL-операций.

### Единый анализатор

- Потоковая обработка технологического журнала.
- Сбор общей статистики по типам событий.
- Передача событий в анализатор производительности.
- Подсчёт количества событий TLOCK и исключений блокировок EXCP.
- Получение статистики SQL-запросов и таблиц.
- Формирование единого набора результатов анализа.

Подробный анализ блокировок, исключений и их последовательностей также доступен через отдельные модули проекта.

### Обработка больших журналов

- Использование SQLite для промежуточного хранения статистики.
- Пакетная запись данных.
- Создание индексов после загрузки данных.
- Контроль потребления оперативной памяти.

## Установка

Проверенная среда разработки: Python 3.14.6.

Клонирование репозитория:

```powershell
git clone https://github.com/OneCoder1C/1c-log-detective.git
cd 1c-log-detective
```

Установка зависимостей:

```powershell
python -m pip install -r requirements.txt
```

Для запуска автоматических тестов дополнительно установите pytest:

```powershell
python -m pip install pytest
```

## Запуск

### Установка зависимостей

```powershell
python -m pip install -r requirements.txt
python -m pip install pytest
```

### Базовый CLI-анализатор

Для демонстрации базового сценария используется пример текстового журнала:

```powershell
python main.py sample_log.txt report.txt ALL
```

Параметры:

- `sample_log.txt` — входной файл;
- `report.txt` — файл для сохранения отчёта;
- `ALL` — фильтр событий.

Доступные фильтры: `ALL`, `ERROR`, `WARNING`, `CRITICAL`.

Этот сценарий предназначен для демонстрации базовой обработки текстовых событий и отличается от полноценного анализа технологического журнала 1С.

### Единый анализатор технологического журнала

Для быстрой проверки работы анализатора используйте демонстрационный журнал из репозитория:

```powershell
python run_unified_analysis.py demo/sample_techlog.txt demo/demo_report.txt
```

В демонстрационном журнале содержатся 4 синтетических события: 2 `EXCP` и 2 `SDBL`.

Ожидаемый результат:

- Всего событий: 4;
- EXCP: 2;
- SDBL: 2;
- Время анализа: около 0,03 сек.;
- Пиковая память: около 23,80 МБ.

Показатели времени и памяти зависят от компьютера и условий запуска.

Для анализа собственного технологического журнала укажите путь к входному файлу:

```powershell
python run_unified_analysis.py "путь\к\журналу.log"
```

При необходимости можно указать имя выходного отчёта:

```powershell
python run_unified_analysis.py "путь\к\журналу.log" "analysis_result.txt"
```

Справка по параметрам запуска:

```powershell
python run_unified_analysis.py --help
```

Параметры:

- `log_file` — обязательный путь к технологическому журналу;
- `report_file` — необязательный путь к выходному отчёту. По умолчанию используется `analysis_result.txt`.

Отчёт включает общую статистику событий, счётчики TLOCK и исключений блокировок, показатели производительности, статистику SQL-запросов и таблиц.

## Ограничения

Временная и контекстная близость событий сама по себе не доказывает причинно-следственную связь.

Обнаруженные медленные запросы, блокировки и исключения являются диагностическими признаками. Их причины необходимо подтверждать дополнительным исследованием.

Проект не выполняет автоматическое сопоставление всех событий с исходным кодом конфигурации 1С и не заменяет специализированные средства диагностики СУБД.
