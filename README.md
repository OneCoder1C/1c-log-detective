# 1C Log Detective

![1C Log Detective — диагностика журналов 1С](banner.png)

**1C Log Detective** — инструмент на Python для анализа технологических журналов 1С:Предприятие, поиска проблем производительности, исследования блокировок и группировки исключений.

Цель проекта — помочь разработчикам 1С быстрее находить подозрительные операции, исследовать причины замедления системы и получать структурированную диагностическую информацию из больших технологических журналов.

Проект ориентирован на потоковую обработку данных, снижение потребления памяти и постепенное развитие механизмов расследования инцидентов.

## Возможности

### Анализ технологического журнала

- Разбор событий технологического журнала 1С.
- Извлечение временных отметок, типов событий, длительности и других атрибутов.
- Потоковая обработка больших файлов без загрузки всего журнала в оперативную память.

### Анализ исключений EXCP

- Извлечение и группировка исключений.
- Подсчёт повторений.
- Определение времени первого и последнего появления.
- Анализ исключений, связанных с блокировками.

### Анализ блокировок TLOCK

- Разбор событий блокировок.
- Извлечение характеристик блокировок и ресурсов.
- Исследование последовательностей блокировок.
- Поиск временных и контекстных связей между событиями.

### Анализ производительности

- Сбор статистики длительности событий.
- Группировка SQL-запросов по типу и нормализованному тексту.
- Подсчёт количества выполнений и суммарного времени.
- Расчёт среднего, максимального значения и P95.
- Выявление медленных операций (порог по умолчанию — 10 мс).
- Анализ SQL-таблиц, участвующих в запросах.
- Формирование списка наиболее затратных SQL-запросов.

### Работа с большими журналами

Для хранения промежуточной статистики используется SQLite. Данные записываются пакетами, что позволяет ограничивать потребление оперативной памяти.

## Запуск базового анализатора

Для демонстрации базового CLI-анализатора используется пример текстового журнала:

```powershell
python main.py sample_log.txt report.txt ALL
```

Параметры:

- `sample_log.txt` — входной файл;
- `report.txt` — файл отчёта;
- `ALL` — фильтр событий.

Доступные фильтры: `ALL`, `ERROR`, `WARNING`, `CRITICAL`.

Базовый CLI и единый анализатор технологического журнала пока представляют собой разные сценарии запуска.

## Ограничения

Временная и контекстная близость событий сама по себе не доказывает причинно-следственную связь.

Обнаруженные медленные запросы, блокировки и исключения являются диагностическими признаками. Их причины необходимо подтверждать дополнительным исследованием.

Проект пока не выполняет автоматическое сопоставление всех событий с исходным кодом конфигурации 1С и не заменяет специализированные средства диагностики СУБД.
